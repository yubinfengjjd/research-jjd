# 已确认的 Methods 写作规则

本文件记录作者对基础提示词 `original-methods-prompt.md` 的后续细化，适用于医学研究的通用场景。两者冲突时以本文件为准；当前用户指令优先于本技能。语言与格式见 `journal-style.md`，判断示例见 `examples.md`。每条规则只在一处定义，其他文件只引用对应位置。

## 1. 主线、范围与事实来源

- 章节顺序、科学目的和内容范围，以作者确认的 Figure/Table 规划、写作大纲或研究问题为准。Methods 承接既定主线，不自行更换研究问题或分析范围；同节内可为论证清晰合并、去重和重排。
- 作者决定记录：项目材料目录（大纲所在目录）下如有 `Methods_作者决定.md`，在映射材料前先读取。其中已裁决的事项直接沿用，不再作为冲突上报，也不重新判断；只记为“仍未解决”的缺口，在核查说明中一行带过，不重复展开。决定与当前材料矛盾时（例如代码已改），按第 7 节上报矛盾本身。本技能不自行写入或修改该文件；作者在对话中作出新决定时，在交付时列出建议追加的条目，由作者确认后再写入。
- 只描述本节主线所需的分析及其必要依赖。目录中有某个文件，或代码里能算某个量，都不代表它应进入正文。
- 证据分级：设计文件只证明方案被定义，代码只证明功能存在，实际调用和运行回执才支持“已执行”。注释与实际执行冲突时，以实际调用为准，并按第 7 节记录。
- 大纲内部冲突（如“写作重点”与“代码映射”不一致）时，正文以写作重点为准，不自行扩写为代码中更多的内容，冲突按第 7 节上报。代码中执行了、但写作重点未提及的分析，同样不自行加入正文。例外（作者 2026-10-12 确认）：写作重点未点名，但大纲已把该分析放进某个 Figure 或 Table、且有执行证据的，作为支撑该图表的必要方法用一两句写入正文，并在核查说明第 2 部分注明依据（大纲中的图表位置与执行证据）。只出现在代码映射、没有对应图表的分析，仍不写入。
- 结果量定义（作者 2026-10-12 确认）：写作重点已纳入某项分析，而大纲的 Results 部分要报告这项分析的某个具体量（如错误率、覆盖率、捕获率）时，Methods 用一句话写清该量的定义。定义与常规理解不一致时（例如错误率不按最高概率类别计算），除在正文如实写明外，还列入核查说明第 1 部分请作者确认。
- 材料中 `exploratory`、`post-outcome` 等标记只适用于它们实际指向的分析。
- 主线外内部备选分析、代码调试、审批、版本、绘图与排版记录留在过程文件。对注册/正文承诺或主要结论依赖而未执行的分析，公开说明其缺失及结论影响，不以内部记录代替披露。纳排、缺失处理、预处理或参数设置如影响方法含义，简洁保留。

## 2. 正文准入与管理性元叙述

正文只描述已实施且与主线相关的方法。判断每句话的实际功能，不按关键词机械删除。

### 准入标准

正文句子应增加对研究的具体理解：研究设计与数据来源、样本选择、终点与变量定义、分析目的、实施步骤、拟合与评估的数据角色、关键参数或工具用途。若删去某句只会少一项管理状态、计划评语、自证承诺或章节提示，而不损失上述信息，就删除该句。

### 排除的表达类型

| 类型 | 通用示例 | 处理 |
|---|---|---|
| 泛化研究性质定性 | “主要终点以外的分析均为探索性” | 不进正文，也不改写为预设或验证性声明 |
| 计划与执行状态盘点 | 与结论无关的内部备用实验进度 | 留在过程文件；正文承诺或结论依赖的缺项须公开披露 |
| 主线外未实施计划 | 尚未承诺、与当前结论无关的候选实验 | 留在内部；必要的验证缺口在局限中说明 |
| 通用审计或诚信自证 | “所有结果均有回执”“未对这些项目插补” | 删除 |
| 空泛章节导航 | “具体流程见下一节” | 删除，在相应节直接写数据用途和方法 |
| 写作者兜底评价 | “不能据此证明……” | 不追加 |

研究性质的总括声明不属于未实施计划，但同样属于应排除的管理性元叙述。

### 必须保留的具体事实

- 正式研究设计、主次终点、拟合与评估的实际关系、具体标签使用，以及必要的样本或类别条件。
- 已实施的数据处理，例如“缺失标签通过掩码排除”“对分析变量采用完整病例分析，不插补”。这与“未开展的项目未插补”这类通用自证不同。
- 同集拟合与评估的关系须在相应方法段写明，不改称独立验证。
- 删除元叙述时不能改变研究事实：不把事后分析称为预设，不把同集拟合参照称为独立验证，不把局部拟合参照扩展为所有方法的上限。
- 图表引用和必要的方法交叉引用，附在具体方法事实之后，不单独成句。
- “描述性”只在准确界定实际分析方式时使用，不作为默认的降格标签。
- 用户明确要求披露某项分析性质时，按要求在适当位置写明。这不恢复泛化声明。

### 事实核对

- 百分比：核对分母和筛选顺序。先留出一部分再从剩余部分划分时，按先后写明，不合并成总体比例。
- 门槛：核对计数对象和有效标签集合。“有标注的单位数”不等于“阳性单位数”。
- 模型范围：对每个模型、对照和消融，分别确认哪些参数被训练、初始化或重拟合。“all”“both”“these runs”须与实际对象范围一致。
- 同时检查两个方向：管理性元叙述已排除，具体数据处理和数据角色仍完整。这是语义检查，不是禁词检查。

## 3. 科学方法名称替代内部编号

- 正文不用内部实验、运行、任务、阶段或脚本编号作方法名称，例如 `R0–R5`、`E-7`、`Wave-2`、run ID、ledger key、notebook 编号、checkpoint 文件名。改用方法名称、数据角色和比较条件。
- 先判断每个条件的性质（内部参照、实际方法、使用标签的拟合参照、诊断分析），不把性质不同的条件统称为同一类算法。
- 内部编号可用于内部映射和核查说明。图表仍使用内部编号时，在核查说明中给出对应关系；未经作者指示不修改图表。
- 不适用于：论文节号、Figure/Table 引用、注册号、软件版本、标准术语，以及与理解相关的数值参数（如 seed、重抽样次数、置信水平）。

## 4. 引用与 PMID

- 引用对象及“标准方法免引”的判断见 `journal-style.md` 第 3 节。
- 对需引用的对象，优先使用原始方法、数据或软件论文。核对题名、作者、年份和 PMID 的对应关系。元数据存在，不等于文献支持所述用法；不用应用论文冒充原始算法论文。
- 按正文实际采用的方法、工具和数据来源逐项检查覆盖，不因已有多条真实引用就判定没有漏引。
- PMID 检索无结果时，核对题名和 DOI，区分“确无 PMID”与“暂未核验成功”。确无 PMID 时，按 `journal-style.md` 第 3 节的顺序取 DOI、正式出版页 URL 或 arXiv，并按第 7 节列入核查说明。核验失败的列为待确认，不报告为已验证。
- 同一方法在适当位置引用一次即可。研究自行定义的比较条件不需要引用。
- 使用正式出版页 URL 的引用（PMLR、JMLR、NeurIPS、ICLR 等不在 PubMed 或 Crossref 的来源）：打开该页面或其会议、期刊元数据接口，核对题名、作者和年份，一致即记为“已核验（出版页）”。页面被浏览器验证拦截时，可用同一作品 arXiv 记录中的发表信息（comment 或 journal-ref 字段）作旁证，并注明旁证来源；这只用于核验，正文标识仍为出版页 URL。核验成功的不列入核查说明第 1 部分。
- 公开检索只提交论文题名、工具名称和标识；代码、数据和未发表正文留在本地。

## 5. 分析目的与表达

- 每个小节或每项独立分析，开头交代它回答什么问题或估计什么，然后写数据、实施和参数。目的句须由大纲或材料支持，不虚构选型理由，不夸大临床意义，不预告结果。
- 目的句不套单一模板。可选写法包括：目的状语开头（“To assess whether …, we …”）；目的并入主句（“Calibration was examined because …”“We estimated … to quantify …”）；以研究问题开头（“Whether … was examined by …”）；或在定义对象后用 “to …” 交代用途。检查相邻段落是否机械套用首句结构；“To …” 和“分析名词作主语 + assessed/quantified/examined/evaluated”等句式的比例仅作诊断，不设硬上限，保留准确自然的表达。能用 “we” 或被动语态说清研究者做了什么时，不把分析、模型或数据写成执行动作的主语（如 “Interventions assessed …”“Joint training aligned …”）。示例见 `examples.md`。
- 修订或扩写时新增的数字和细节，只限于帮助读者理解方法的内容，例如各分区样本量、纳排门槛、关键超参数。属于结果的数字（检验 P 值、实际观测的计数分布、性能值）和实现细节（哈希或去重算法、采样器名称、随机变量来源、文件或接口名）不进正文。每一处新增事实都在核查说明中注明出处（文件与位置）。
- 实现层质控不进正文：数值复现容差、重跑一致性检查、哈希排序、文件完整性、断言通过与否等，属于“我们核对过实现”，而不是“我们做了什么分析”。需要时记入核查说明。
- 但影响结果含义的设计选择应保留：抽样是否依赖预测、随机种子数量、确定性选择规则等，用科学语言概括，例如写 “a deterministic, prediction-independent sample”，不写 “SHA-256 hash of path”。
- 写明重要 R package 或 Python library 的名称，并用一句话说明其在本研究中的功能，不列出无关依赖。
- 句式变化服务于信息组织，术语保持稳定。不靠同义词轮换、强行倒装或连续同一开头来制造变化，也避免“先……再……然后……”式的流水账。
- 采用 ARS 质量指导（`ars-style-excerpt.md`）时，其固定段落结构服从本任务：不强制每段写总结句，不添加结果、讨论或宣传性句子。

## 6. 中英对照与标题层级

- 默认英文正文后接逐段中文对照。两种语言的方法名称、参数、数据角色、引用和限定范围保持一致。
- 中文对照按中文学术语序重组：可合并英文中的短句、调整从句顺序、把被动改为中文习惯的主动或无主句，但不增删事实和限定。避免“被……所”“对……进行……”的堆叠和逐词直译。对照示例见 `examples.md`。
- 每个小节一个标题，概括内容与目的；中英标题可合并显示。作者已确认的标题优先。
- 完整 Methods 保留大纲中的父级总括标题（如 `2.3`），不只写叶节点（`2.3.1`）。父级标题下不另写概述段，除非大纲或作者要求。
- 单节续写进入新父节时，先补父级标题。“下一节”依据大纲和写作进度定位；找不到进度时先查稿件或记录，仍无法确定再询问，不跳节。

## 7. 核查说明

核查说明是独立的中文文件（单独保存时命名为 `Methods_核查说明.md`），或对话中的独立说明块。正文不夹带审计评论，核查说明的内容也不拼回正文。

### 触发清单（命中任一项必须输出）

1. 正文中有任何需引用对象使用了非 PMID 标识：每个来源一行，写明来源、所用标识和“确无 PMID”的核验依据（或“暂未核验”）；已用 PMID 的引用不列。
2. 大纲内部冲突，或大纲与代码、回执冲突：写明双方原文、位置，以及正文采用了哪一方。
3. 代码执行了、但大纲写作重点未纳入正文的主线相关分析：写明未纳入的原因，请作者裁决。
4. 必要主线方法缺少执行证据，或重要方法事实无法核验：写明具体缺口和需要补充的材料。
5. `journal-style.md` 第 4 节规定的缺口：伦理或数据使用声明、软件版本、报告规范缺失的关键要素。
6. 图表或图注仍使用内部编号时，给出编号与正文方法名称的对应关系（第 3 节）。内部编号只出现在代码或回执、图表和正文都不用时，记“未命中”，不列对照表。写作者无法读取成图或图注（例如访问范围不含 Results 图件）时，不按源数据推断图表用了内部编号；第 6 项只写一行“无法核读成图，未判定”，不列对照表。
7. 修订任务中，旧核查说明的条目被本次修订推翻或已经过时（见第 8 节）。

只有全部七项都不命中，才可以不输出核查说明，并在交付时说明“核查说明触发项均未命中”。

已在 `Methods_作者决定.md` 中裁决的事项不触发第 2、3 项；记为“仍未解决”的缺口只在第一部分一行列出（第 1 节）。

### 结构（按此顺序，只写这三部分）

1. **需作者裁决或补充的事项**：放在最前，每条写明问题、正文当前的处理、需要作者给出的决定或材料。这是核查说明的主体。
2. **七项触发结论**：每项一到两行，写命中或未命中及要点；命中项的细节只写作者判断所需的内容（如冲突双方原文与位置），不展开核对过程。
3. **新增或改动事实及出处**：简表，每条一行，列“正文事实 | 修正、新增或删除 | 出处（文件与函数或行号）”。修订任务中旧核查说明条目的处置（触发第 7 项）也合并进这张表或用一行概括，不另起逐条长表。

逐句回查表、证据定位索引、全文引用清单、交付检查记录等过程材料不进入核查说明。写作者需要留存时放在工作目录，交付时说明位置。

### 内容规范

- 区分“大纲原文”“代码或回执记载”“作者最新决定”“写作者推断”，不把推断写成材料原文。
- 不收录主线外的未来实验、计划状态、空泛导航、通用自证、没有具体发现的防御性声明，或“全部检查通过”式的笼统总结。
- 核查说明声称某处已修正时，逐项回查正文是否已落实。
- 篇幅以作者能一次读完为准：没有需裁决事项的修订，核查说明通常不超过一页；条目多时压缩措辞，不靠拆表增加篇幅。

## 8. 修订模式

用户要求修改、润色或重写已有 Methods 稿时，按以下步骤执行：

1. 读取旧稿、旧核查说明（如有），并与首次写作一样完成大纲和材料映射。旧稿不能替代材料，旧稿中的事实同样要回查代码。
2. 逐节通读，按现行规则判断，再整段重写。不用脚本对旧稿做字符串替换或局部打补丁；局部补丁容易留下前后矛盾、过时限定和旧文风。
3. 修改不限于明显错误，也包括目的句、缩写、术语、引用格式和篇幅（`journal-style.md`）。
4. 重新生成核查说明。旧条目逐条判断为保留、更新或作废；对作废条目说明原因。不保留与新正文矛盾的旧说明。
5. 事实句逐句回查：新稿中所有事实句，包括从旧稿原样保留的句子，都逐句对照代码、配置或回执；旧稿已有的错误同样要找出。重点核对三类：拟合用的是哪个数据分区、评估用的是哪个数据分区；模型或输出头的结构（线性或带隐藏层、冻结或微调范围）；全称表述（“each … one component”“all models”“both”“identical”）是否对每个对象都成立；样本量和计数的单位（扫描、眼、受试者、体积、扫描–概念对、配对等），每个 n 都对照产生它的代码，确认它数的是什么。从旧稿原样保留的数字句同样逐个核对，不因“上一稿已写”而跳过。新增且无证据支持的事实不写入；既有句子因局部材料缺失无法回查时，保留该处并登记具体未知范围与证据需求，继续独立编辑。明确证据冲突按影响裁定，核心矛盾阻断受影响交付，不以静默删句解决。回查是写作步骤，核查说明只报告结果中的改动（第 7 节第 3 部分），不收录回查过程。
6. 在对话中给出简短的修订摘要，按节列出主要的事实性修改。摘要不写入正文。
7. 处理脚本、检索缓存等中间文件不留在稿件目录。如需保留，放在用户指定的工作目录，或在交付时说明其位置。

## 9. 范围与验收

- 默认只处理要求的 Methods 小节或全节，不改写 Figure legend、Results、大纲、代码或数据。
- 遵守当前任务的访问限制和材料隔离要求。研究内容本地处理，不发送到其他服务。
- 只对会改变写作范围或方法含义的真实缺口提问，复用作者已确认的决定。
- 交付时区分“正文已完成”“引用已核验”“仍待确认”，并报告英文词数。格式检查通过只能证明结构有效，不能替代对科学事实和引用的核查。
