# 自适应实验的计划与资产状态衔接

仅在 `medimg-experiment` 已明确启用作者授权的自适应执行、或读取其结果事件时加载。本技能维护路径/索引和下游状态；模型修订、训练、审查、预算和测试门由执行技能负责。不开第二个实验控制器，不新增论文阶段编号，也不把实验迭代当作每个论文阶段的作者确认。

## 1. 路径与身份

| 路径 | 内容与更新规则 |
|---|---|
| `00_plan/project-plan.md` | 当前可独立阅读的研究计划；真正更新技术路线、方法假设、实验与下一任务 |
| `00_plan/session.md`、`review.md` 等 | 初始真实 G1/G2/G3、执行授权来源与修订历史；授权内新方法标自动修订，不造新的人类确认 |
| `01_analysis/README.md` | 总索引；列来源、当前计划、study/report 路径、最新尝试/当前有效/最终冻结三个视图、测试暴露及待核项 |
| `01_analysis/<study-id>/plans/` | 初始确认计划不可变快照与哈希、各修订契约及授权引用 |
| `01_analysis/<study-id>/` 其他受控内容 | 代码/候选/runs/tests/审查/诊断/恢复与失效/负结果证据、事件和报告；原位保留，不搬家、不改名 |
| `_process/plan/<日期>_<描述>/` | 跨技能修订说明、依赖影响核对等过程材料 |
| `_archive/<日期或日期_2>/<原相对路径>` | 被新版本替换的计划、README、review、PROJECT 等旧文档；按批次唯一归档、只增不改 |

没有 `PROJECT.md` 时不由本参考创建项目骨架，遵守独立技能既有路径；已存在的 study 不自动迁移。外部 study 只登记授权路径，不擅自搬入项目。

## 2. 同一事件的三种证据视图

三个视图都用稳定候选/run/评价版本、原始路径和来源条件，不能用“最近文件”代替：

- **最新尝试**：可以是筛选、不达标、程序失败或已失效；注明实际证据等级和失败原因。
- **当前有效证据**：已核验基线、完整正式结果及条件仍适用的复用结果。筛选结果不冒充正式证据；相关预处理、指标实现、数据或依赖变化须审查影响并沿选择/训练链失效。不相关的旧有效基线不因新候选失败而丢失。
- **最终冻结方案**：正式所有比较/贡献及多 seed 规则达标后才有；明确模型/seed/评价清单和测试未暴露/部分暴露/已暴露。未冻结就写“无”，不能用 latest 填充。

固定任务、标签、患者划分、评价科学定义、贡献目标和全局预算不改。原模块失败只允许在委托范围内改造/替换实现，不能删除目标宣布 accepted。测试结果不反馈方法搜索；测试后评价纠错需真实作者新确认。这些门由执行技能判定，目录同步不能替代或放宽。

## 3. 触发事件与主文更新

基线核验、方法修订、筛选晋级/淘汰、正式复核、故障修复、评价纠错、条件复用/失效、恢复、预算/截止停止、冻结和测试完成都同步项目投影。使用与 study 事件一致的身份和原始证据，不把助手叙述当执行回执。

当前计划至少保持：固定目标/边界；当前方法与可证伪机制假设；最新尝试和状态；当前有效基线/正式证据；未满足贡献、负结果和失效原因；本轮旧新路线、诊断依据；下一任务/依赖；跨版本余额/正式证据预留/绝对截止时间；代码/候选/run/评价身份；测试暴露状态。方法变化时修订对应章节和任务，不能只在末尾追加运行日志。

执行报告区分科学达标、有效负结果、程序错误导致的失效和资源不足造成的未完成；已存在的结果仍保留原始科学结论，历史主张如被反驳记清原因。

## 4. 归档、同步和重入

由 `medimg-experiment` 实际同步器执行事件投影。一次同步应有事件身份、单写锁、目标旧内容/哈希、唯一归档批次、新内容和同步回执；先归档验证，写临时文件，再原子替换各目标。多个文件、Git 与文件系统不是天然单一事务，不能只因单文件使用 rename 就宣称整体原子。

重入先核对该事件的回执和已发布内容，补完未完成投影，不重复归档同一事件、不覆盖归档、不重复启动训练。发生并发变化、缺归档、磁盘不足或哈希冲突时保留证据并停止相关投影，协调修复后继续；不删除旧结果腾空间。同步未完成就不能报告计划与索引已一致。

`PROJECT.md` 的目录说明登记计划/study/report/测试状态，变更记录记事件与归档/回执；**不增加“实验”阶段行**，不改写历史作者确认。总 README 与 PROJECT 要引用同一状态；原来存在的其他目录说明、来源和写作目标保留。

## 5. 传播下游影响

按实际依赖标记受影响的图表规划/成图、大纲、Methods/图注/Results 及进一步依赖的 Introduction/Discussion/Abstract/成品/引用/期刊适配与投稿材料为 `需返工`，记录受影响的证据、路径和理由。仅程序失败且未改变当前有效依据，不因 latest 失败把无关下游一律失效。

同步只更新状态和影响登记，不擅自改数字、重画图或重写正文；作者请求进入相应阶段时才调用该技能，仍遵守阶段原有门槛。实验正式达标也不自动把任何论文阶段改为 `已确认`。

## 6. 核查与能力边界

在隔离夹具验证旧文档归档不覆盖、原 study 路径/哈希保留、同一事件重入、故障后的同步补完、三种视图以及下游状态。已有 `intake_check.py` 检查 study 结构/总索引登记，不核验自适应授权、预算、测试门或投影事务；`consistency_check.py` 也不证明科学有效性。

没有原始回执时只说明已读/已更新的文档；未完成真实 GPU 训练、所选 CLI 后端的新上下文审查、跨候选无人值守或锁屏实测时明说未验证。合成执行测试只支持程序行为，不替代真实医学数据或临床验证。
