# 实验协同的计划与资产状态衔接

当论文项目通过 `medimg-experiment` 开展受管实验并同步结果时加载本参考。本技能维护项目目录约定与下游阶段状态；划分审计、训练执行、路线修订与测试集隔离由 `medimg-experiment` 负责。

## 1. 目录与单份活计划书约定

| 路径 | 内容与更新规则 |
|---|---|
| `00_plan/project-plan.md` | **唯一活跃计划书**：始终与当前实验路线同步，纯可读 Markdown（不留草案文件、不塞裸 JSON 或折叠历史）；定稿后仅保留唯一最终路线 |
| `01_analysis/README.md` | 总索引：维护各 study 的当前状态、路线版本、有效验证集均值 ± SD、基线复用来源与锁定测试状态 |
| `01_analysis/<study-id>/` | 受管实验目录：包含 `config.json`、`state.json`、`routes.jsonl`、`runs/`、`tests/`、`evidence/`、`plans/history/`、`report.md` / `report.json`；原位保留不搬家 |
| `_archive/<日期>_plan_v<N>/00_plan/project-plan.md` | 每次路线修订或定稿替换前自动归档的旧版计划书；只增不改 |

没有 `PROJECT.md` 时不新建论文项目骨架；历史计划快照保留在独立 study 的 `plans/history/` 下。

## 2. 同步与下游返工规则

- **无外部编辑互锁**：作者或其他写作技能随时可以直接修改 `00_plan/project-plan.md` 与 `PROJECT.md`，`medimg-experiment` 不会因外部编辑而报错停机；每次更新计划书前先完整归档旧文件，再原子写入新版。
- **不增加实验阶段行**：`PROJECT.md` 仅在 `## 变更记录` 追加简洁事件摘要，不新增“实验”阶段编号，不自动把任何论文阶段改为 `已确认`。
- **定稿触发下游返工标记**：仅当实验执行 `finalize` 确认新的最终路线时，把此前已完成且依赖实验结果的下游阶段（如已确认/待确认的图表规划、成图、大纲与正文阶段）标记为 `需返工`（第 0 步入口检查与开题阶段保持不动），避免探索期中途波动反复刷写下游状态。
