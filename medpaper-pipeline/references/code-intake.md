# 代码接收与整理

## 1. 适用情形与前置

本流程位于阶段 0“入口检查与代码整理”内，在阶段 1 可视化规划之前；不新增阶段。

| 情形 | 处理 | 登记 |
|---|---|---|
| S1 复盘项目：已跑完、代码散乱 | 按已确认思路复制、重命名并迁入 `01_analysis/` | 来源目录、总索引与 PROJECT.md |
| S2 项目内 study | 只核验登记，不复制、不搬家、不重命名 | 总索引与 PROJECT.md 目录说明，不写阶段状态表 |
| S3 无代码与结果资产 | 不执行整理 | PROJECT.md 备注“代码整理：不适用” |

必须先有已确认的思路来源：`00_plan/` 计划或作者研究问题说明。缺失时停下，请作者补充并说明缺什么；不代写、不推断开工。既有已整理项目不追溯。

## 2. 结构与映射

```
01_analysis/
├─ README.md              总索引：各来源一览、与 00_plan 的对应、待核项
├─ <来源名>/               每个代码来源一个目录（来源名由整理方案定，作者确认）
│  ├─ README.md           复现说明：来源（原绝对路径＋日期）、环境、运行顺序摘要、无回执声明、待核项
│  ├─ 映射表.md           步骤映射表（列定义见下）
│  ├─ code/               脚本与配置；命名 `<两位序号>_<语义名>.<ext>`，序号＝运行顺序；内容零改动
│  ├─ results/            结果资产（指标表、划分文件、日志等；保持原名，重名冲突由方案定并记录）
│  └─ receipts/           执行回执与运行日志；无则 README 注明“无回执”并列入待核项
└─ <study-id>/            可选：medimg-experiment study（其受控结构，不重排）
```

映射表固定列：

| 序号 | 整理后路径 | 原路径 | 运行命令 | 前置序号 | 产出 | 对应图表 | 备注 |
|---|---|---|---|---|---|---|---|
| 01 | code/01_summarize.py | 原绝对路径/summary.py | 未知 | — | results/metrics.csv | Table 1 | 命令待核 |
| — | results/metrics.csv | 原绝对路径/metrics.csv | — | 01 | — | Table 1 | 保持原名 |

- 整理后路径相对 `<来源名>/`，限 `code/`、`results/`、`receipts/` 内；每个复制文件一行，保留“原路径 → 整理后路径”对照，原路径为绝对路径。
- 代码序号与文件名前缀一致（两位数字），序号即运行顺序；配置随所属步骤编号。运行命令未知填“未知”，在 README 待核项列出；不凭命名推定依赖或补写命令。
- 产出指向 `results/` 或 `receipts/` 文件；没有对应图表填“—”。结果与回执保持原名，重名冲突在方案中先定并记录。
- 多来源各建目录；外部仓库且作者选择不迁移时，`01_analysis/` 只放 README.md 写明路径与 commit；这是作者选择项，默认结构整理迁入。

只复制文本代码、配置与小型结果资产；原始数据、模型权重、凭证默认拒绝。例外逐文件列入方案，经作者确认后在该文件映射表备注写“作者批准”。黑名单扩展名为 `.pt .pth .npz .safetensors .ckpt .bin .h5 .sqlite`，不能仅靠扩展名判断其他原始数据或凭证是否可复制。

符号链接一律不复制、无批准例外；源目录中的符号链接作为排除项列入整理方案，不跟随链接复制其目标。原目录完全不动；整理不包含重构、修补路径、安装环境或实跑验证。

## 3. 七步流程

| 步骤 | 操作 | 记录与关口 |
|---|---|---|
| 1 读思路 | 读取已确认计划或作者研究问题说明 | 写明来源、版本与对应研究步骤；缺失即停 |
| 2 盘点 | 建立脚本↔产出、产出→图/表（若有）的对应，收集环境与命令线索 | 显式列出未知，不把读过代码写成运行成功 |
| 3 整理方案 | 列目录、逐文件复制清单（原→新）、重命名表、步骤映射、排除项与理由、待核项 | 原始数据/权重/凭证例外逐项列明；符号链接只列排除项 |
| 4 作者确认 | 获得对完整方案的明确确认才执行 | 拒绝则修订重提，不得部分执行或先复制后补确认 |
| 5 执行 | 按方案只复制、只改文件名；code/ 按序命名；内容零改动 | 对照复制清单逐文件核对字节或摘要；原目录不动 |
| 6 生成 | 生成来源 README 与映射表，更新总 README | 来源＝原绝对路径＋日期，环境、运行顺序摘要、无回执声明与待核项齐全 |
| 7 登记与归档 | 核验通过后，在 PROJECT.md 目录说明与变更记录追加 | 过程记录、旧版归档均可追溯；error 未清零不得登记收尾 |

过程记录写入 `_process/Intake/<YYYY-MM-DD>_<描述>/`，包含盘点记录、方案与作者确认记录。被替换的旧 README/映射表（含总 README）先归档 `_archive/<日期>/<原相对路径>`，同日多次用日期后缀区分，不覆盖旧归档。

来源 README 至少说明：原绝对路径与接收日期、对应计划、环境证据、运行顺序摘要、实际命令或“未知”、已有回执；无回执明确写“无回执”并列入待核项。总 README 汇总各来源、与 `00_plan/` 的对应和待核项。整理完成只说明结构与复制核验结果，不宣称代码可运行或研究已验证。

核验示例（在本技能目录下，项目根替换为实际路径）：

```powershell
python -X utf8 scripts/intake_check.py <项目根>
```

核验检查结构、映射双向一致、命名、黑名单与符号链接；error 退出码 1，warning 不影响退出码。warning 逐条说明；映射语义、思路与结果是否对应仍由盘点及作者确认保证。

## 4. study 核验与增量接收

- study 根默认 `01_analysis/<study-id>/`，作者另行指定优先；全新目录，不与原数据/源代码目录重叠，`init` 会创建父目录。
- S2 核对 study 目录存在、`plans/`、`state.json`、`report.md` 与登记；内部结构由控制器管理，不要求来源映射表。核验脚本按 `plans/` 与 `state.json` 识别 study，并检查总 README 提到其目录名；report 与锁定测试状态由本流程核对，不冒充脚本已核验。
- 在 `01_analysis/README.md` 与 PROJECT.md 目录说明登记 study 路径、`report.md` 与锁定测试状态，不写阶段状态表。作者指定项目外 study 时在 README 写明外部路径，本流程按授权核对，脚本不沿外部引用读取。
- 自适应 study 的后续计划/索引更新按 [实验状态衔接](adaptive-state.md)。最新尝试、当前有效证据、最终冻结方案分别索引；原位保留失败/负结果和失效链。不对 study 应用来源代码的文件序号、映射重命名或“半成品归档后重做”规则，不因同步中断重跑训练。
- 增量接收不重排既有来源；新来源加目录并更新总 README。以来源目录为执行单位；未完成不登记 PROJECT.md，重入时先将半成品归档，再按已确认方案重做；方案变化须重新确认。

## 5. 下游衔接

- medfig-plan 继续按“`01_analysis/`（或其 README）只读盘点”，不改其行为。
- 口径表与写作技能的既有代码出处经该来源映射表回溯，不批量改写；新引用使用整理后路径与重命名后的文件名。
- 无 `PROJECT.md` 时保持原有行为，不将本子流程追溯应用于现有独立项目。
