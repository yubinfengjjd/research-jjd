# 已确认的 Discussion 写作规则

本文件细化基础提示词 `original-discussion-prompt.md`，适用于生物医学、临床与基础医学研究的 Discussion。两者冲突时以本文件为准；当前用户指令优先于本技能。语言与格式见 `journal-style.md`，判断示例见 `examples.md`。每条规则只在一处定义，其他文件只引用对应位置。

## 1. 前置条件（硬门槛）与材料

Discussion 在其他正文全部完成后才写。开始前确认以下四份稿件都已存在且完整：

| 稿件 | 完整的标准 |
|---|---|
| Methods | 有正文段落，不是提纲 |
| Results | 每个研究问题都有正文段落；没有 TODO、待补、`[xx]`、`XX%` 等占位 |
| 图注（主图；有附图、表格时也包括） | 每张 Results 中引用的图表都有图注 |
| Introduction | 有正文段落，提出了研究空白和研究问题 |

- 四份都在且完整：正常起草。
- 缺任一份或任一份不完整：列出缺什么、缺在哪里（文件和段落），说明补齐后再写，然后停止。不起草、不写“保守版”、不写部分段落。作者坚持也一样，可以建议对应技能（medical-sci-methods / -results / -legends / -introduction）。
- 只有一份完整手稿（docx 或 PDF）时，把手稿中的对应章节当作这四份稿件，同样逐项检查。
- 目标期刊、引用格式、语言偏好是可选输入，缺了不阻塞：按默认策略写，并在核查说明中记录。

| 材料 | 用途 |
|---|---|
| Results 稿 | 唯一的事实来源：可讨论的发现、数字、范围和例外 |
| 图注 | 核对图表实际展示的对象和定义；不从图注引入 Results 没写的结果 |
| Introduction 稿 | 本研究提出的研究空白和问题；Discussion 必须逐一回应；首选文献池 |
| Methods 稿 | 设计、数据、模型和分析的名称与定义；局限性的主要依据；文献池 |
| 写作大纲 | 研究问题和措辞边界；大纲中的结论句只是写作意图，不作事实依据 |
| 口径表、作者决定、冲突台账（存在时） | 术语、计数和已裁决事项直接沿用 |

- 材料之间冲突时，按 Results 和 Methods 实际写了什么来讨论，并在核查说明中列出冲突和可核对的依据（段落、表格行）。已裁决的不再列。
- 不新增分析、不读原始数据补算数字。需要 Results 没有的分析才能支撑的论点，不写，或在核查说明中建议作者补分析。

## 2. 结构

默认无小标题，连续成段，一般 6–9 段。五个部分按顺序推进，最后加结论段：

1. **总结与背景**（1 段）：一句回到 Introduction 提出的问题，再用 2–4 句概括主要发现及其为何重要。不重复 Introduction 的疾病背景，背景最多一句。
2. **结果解释**：围绕核心发现说明其证据含义、与已有工作的关系和适用范围；有依据时解释可能原因，不能为完成段落模板补造机制或假说。
3. **文献对比**：按证据关系单独或融合呈现，与最接近、可比的已有工作具体比较，不要求每个发现固定两篇或每段强制一轮比较。
4. **创新与贡献**（1 段，或并入总结段或文献对比段的末尾）：本研究回答了 Introduction 中的哪个空白，补充或改进了什么，对谁、在哪个判断环节有用（第 6 节）。
5. **局限与未来方向**（1–2 段）：以 “This study has several limitations.” 或同类句开头（第 7 节）。
6. **结论**（2–4 句）：只复述证据支持的主要结论及其适用范围，不引入新内容、新引用或新数字。期刊要求独立 Conclusions 时拆出，标题按期刊要求。

- 五部分都必须出现，不得缺项；第 3、4 部分可以融合进其他段落，但在核查说明的对应表中要能指出位置。
- 作者或目标期刊要求小标题时，按要求使用（如 Principal findings、Comparison with previous studies、Strengths and limitations、Conclusions）。
- 段落之间用内容衔接；每段开头一句点明本段讨论哪个发现或哪类问题；不写“In this section”“The remainder of the Discussion”之类的导航句。
- 解释段末不加泛化的复述句（“Together, these comparisons favor …”“X therefore address complementary questions”“… remain empirical questions”）。段末句要么是本段推出的具体含义（对谁、在哪个环节），要么直接结束于最后一个解释或比较。检查是否机械重复 Together / therefore 收尾，保留有据的新信息，不设全文硬次数。
- 局限段可以用 First / Second / Third 列举局限，其他段落不用这类路标。
- 不在正文中提及稿件其他章节（“the Introduction's questions”“as described in Methods”“the Results showed”）；回应 Introduction 的问题时直接复述问题本身。
- 设计细节（骨干网络、训练设置）只在解释某个发现必需时提一句，不为介绍它新增引用。

## 3. 选准重点

- 从 Results 中按研究问题和证据重要性选择核心发现深入讨论，2–4 个仅作规划参考。选择顺序：直接回答 Introduction 研究问题的发现 > 出乎预期或与已有文献不一致的发现 > 对解读主要结论必需的辅助分析（如敏感性分析、失败模式）。
- 其余发现按结论相关性简述或省略；不逐节复述 Results 目录。在核查说明的对应表中列出未展开的发现及理由。
- Introduction 提出的每个研究问题，Discussion 都要回应；Results 中与主要结论方向相反的发现、例外队列或亚组，至少一句如实讨论，不回避。
- 篇幅分配向核心发现倾斜：解释与文献对比合计一般占全文一半以上；总结段不超过约 200 词。

## 4. 结果的使用与解释的边界

### 数字

- Discussion 不复述 Results。只在解释需要时引用关键数字，不设每段数字硬上限（如说明差距的大小、例外的程度）；不列表式堆砌指标、区间和 P 值。
- 引用的每个数字、范围、计数与 Results 稿逐字一致（含单位、小数位、区间类型）；不做 Results 中没有的换算、平均或合并。
- 不写 Results 未报告的结果、亚组或趋势；不用“numerically higher”“a trend toward”把未检验或不显著的差异写成发现。

### 推断强度

- 每个解释句都要能指出依据：本研究的哪项分析（Results 段落），或哪篇文献。候选解释须有可核对的事实或文献依据；尚未直接检验时写成假设并按需要说明验证方式。连候选依据也没有时保留未知，不用 may 掩盖无据解释。
- 措辞强度与证据匹配：
  - 本研究直接检验过的：indicate、show（指本研究数据显示的现象）、were associated with；
  - 由本研究结果推测的：suggest、may、could、is consistent with；
  - 只由文献支持、本研究未检验的机制：may、possibly，并写明来源（“previous work has linked … (PMID: …)”）。
- 不用 prove、confirm（指本研究的假设）、establish、for the first time、novel、clearly、undoubtedly。
- 不用因果和定位动词（causes、drives、is responsible for、arises at、由……造成、发生在……这一步），除非设计本身支持因果推断（如随机对照、干预实验）；观察性或回顾性设计写 associated with、coincided with、was accompanied by。
- 同一段内的对冲词不叠用（不写 “may possibly suggest”）；整段都是推测时，开头一句标明是推测即可，不每句加 may。
- 模型研究中，“模型学到了什么”只写数据或探针分析直接显示的内容，不写模型“理解”“知道”“推理”。

### 解释服从证据

- 核心发现段须增加读者对证据的理解，可以解释实际意义、边界、与其他发现/文献的关系；不强制每段给候选原因或提出检验。候选机制须有本研究或文献依据并明确未检验性质；证据不足时如实保留未知。
- 例外和不利发现须如实讨论其对结论的影响；只有材料支持时才给候选原因，无据时说明原因未知，不靠推测淡化失败。
- 每个核心发现段中，复述 Results 的句子（无论带不带数字）不超过约三分之一；该比例仅作重复诊断，具体句数服从证据逻辑。次要分析（探针序列、附加终点、单例图库、子分析）只在它是解释的依据时提一句，不顺带搬入。
- 候选原因后的检验建议（“… would test / distinguish …”）按重要性选择，不固定条数；其余可区分的检验并入局限段的未来方向，不在每段末尾重复同一句式。
- 边界靠限定词守，不靠否定句堆叠：“does not imply / does not establish / cannot be assumed / does not identify”这类否定式限定句不逐段套句式，数量仅用于发现重复，不是硬上限；可合并的改为带范围的肯定表述（“within these cohorts”“for the edema-related concepts”）。

### 机制与临床意义

- 机制解释必须有文献支持或有本研究的直接分析；两者都没有的机制，不写。
- 临床意义限于本研究设计能支撑的环节（如筛查前评估、部署前检查、审阅模型解释时），写明对谁有用。不写改善预后、改变指南、降低成本、可直接用于临床等材料不支持的外推。
- 回顾性、单中心、公开数据集或无前瞻验证的研究，临床意义句中写明需要前瞻验证，在相关意义段或局限段说明，避免机械重复；不同论断需要不同范围时分别保留。

## 5. 文献对比

- 文献比较选择直接相关、最接近且定义可比的研究，说明对方条件、发现与本研究关系；数量由论证需要决定，“两篇”仅作参考，不补引弱相关研究，不扩展篇幅以满足篇数。
- 结果不一致时，给出 1–2 个可能原因，并落在可核对的差异上（数据来源、人群、设备、标签定义、评估指标、样本量、模型类别）；不写“may be due to differences in study design”这类空泛原因。
- 比较数字时，只比较定义一致的量；定义不同（如 AUROC 与 balanced accuracy、患者级与图像级）时说明不可直接比较，不并列数字。他人的数字必须由所引文献摘要或正文给出，写入前核对。
- 每处比较都让读者看出关系是一致、不同还是扩展，不只把对方的研究和本研究的发现前后并列。关系靠内容表达（“Like X, …”“Whereas X evaluated …, we …”“X reported … ; in our cohorts, by contrast, …”），不套固定句式：agrees with、extends、is consistent with、contrasts with 的重复仅作诊断，不设词频硬门槛。
- “扩展”只在对方确实检验了本研究所检验内容的一个子集时使用（如对方只评估最终分类，本研究另评估了解释稳定性）；对方没做过可比检验的，不硬说本研究扩展了它。
- 转述他人发现的强度不超过其摘要或正文：摘要说“detected systematic differences”，不升级为“became miscalibrated”。
- 文献只为比较或解释而引：创新段、意义段不为“显得有对话”新引一篇关联较弱的研究；与本研究核心发现没有直接可比之处的文献不引。
- 不贬低已有研究，写对方的设计条件而不是评价（“was evaluated on a single device” 而不是 “was poorly validated”）。
- Introduction 中作为研究空白依据的关键文献，Discussion 应在对应发现处回应一次（本研究在哪一点上补充了它）；不重复 Introduction 的综述。

## 6. 创新与贡献

- 贡献写成“回答了哪个空白 + 与最接近工作的具体区别”，与 Introduction 提出的空白一一对应；不写 Introduction 未提出的新贡献。
- 不用 novel、first、unprecedented、breakthrough、groundbreaking、paradigm-shifting、state-of-the-art（无引用时）。确需表达首次性时，只用 “to our knowledge” 限定，与 Introduction 的检索依据一致，避免重复强调，不以次数替代证据核对。
- 意义句写明对谁（临床读者、模型开发者、评估者、监管或采购方）、在哪个判断环节有用；不写没有对象的“has important implications”。

## 7. 局限与未来方向

- 局限按对结论影响排序，数量依实际设计与证据而定，不为凑三条虚构局限。每项说明具体局限、影响哪个结论及其范围，并写已有应对或相应未来方向。
- 局限的来源：Methods 中的设计与数据条件（回顾性、单中心、公开数据集、标签来源、样本量、设备覆盖、缺失数据、超参数选择）、Results 中暴露的例外和失败模式、核查说明或作者决定中记录的范围限制。按实际影响覆盖设计、数据及分析层面的重要局限，不以分类配额要求增写。
- 敢讲：Results 中不利于主要结论的发现、未达预期的分析、方法上有已知缺陷的部分，要在局限中如实写出，不淡化、不只写“small sample size”这种通用局限。
- 不用局限否定自己的主要结论；也不在局限后紧接“nevertheless, our results are robust”式的找补，除非 Results 中有对应的敏感性分析。
- 未来方向具体可操作：写需要什么数据、什么设计、检验哪个问题（“prospective evaluation on scans from devices not represented here”），不写“further studies are needed”这类空话；每条未来方向都对应一条局限或一个未解答的问题。

## 8. 文献检索与核验

### 文献池与优先级

1. 手稿已有引用优先：先用 Introduction 和 Methods 中已核验的文献；它们的核查说明或引用元数据文件中已有的核验记录可以沿用，但仍要用公开数据库再核对一遍题名、期刊和年份。
2. 不足时检索 PubMed 补充，重点找能与本研究核心发现直接比较的研究，以及支持机制解释的研究。检索只提交公开的主题词和术语，不提交手稿正文、未发表数据或代码。
3. 期刊层级按 `journal-style.md` 第 3 节判断，不写影响因子数值。同等相关性下优先近 5 年、高层级期刊的原始研究；相关性始终优先于期刊层级和发表年份。

### 每条引用的核验

- **真实性**：每个 PMID 都用 Europe PMC REST API 或 NCBI E-utilities（esummary）核对题名、第一作者、期刊和年份。核对不上或请求两次失败的，不写入正文。
- **支持关系**：读摘要（必要且可获取时读全文），确认它支持正文中所述的那句话；用于数字比较的，确认数字和定义出自该文献。
- 不用综述冒充原始研究；描述某项研究的发现时引该原始研究。临床论断引临床研究、指南或权威综述，不用数据集或算法论文支撑。
- PMID 紧跟它所支持的研究或论断；一句描述两项研究时分别标注。一个论断引 1–3 篇。
- 与 Introduction 重复引用同一文献是正常的；但 Discussion 内同一文献一般只在最相关处引一次。

### 数量与缺口

- 读取 PROJECT.md“写作目标”的 Discussion 既有软配额；无登记时历史 ≥20 篇仅作参考，记录配额来源，不建立新的硬门槛或提高目标。按论证缺口检索，不能为填数扩大文献池或正文；直接比较不要求每发现至少两篇。不足时完成证据可支持的稿件，报告实际 vs 目标及真正的支持缺口。
- 确无 PMID 的关键文献按 `journal-style.md` 第 2 节降级标注；降级文献分列，不计入本节 PMID 配额。
- 确需引用而检索后仍找不到可核实文献时，正文在该处写 `[citation needed]`，并在核查说明第 1 部分列出：该句、检索过的主题、需要作者提供什么。不编造、不用相关性弱的文献凑数。可以改写为不需要引用的表述时，优先改写。

### 请求规范

- 请求顺序发送，间隔约 1 秒，每个请求限时；遇到 HTTP 429 等待约 30 秒再重试一次。
- 检索与核验的中间结果只留在临时目录，不写入稿件目录。

## 9. 中英对照

- 英文正文后另出中文稿和逐段对照稿。中文与英文的事实、数字、引用、限定和对冲强度一一对应，不增删内容。
- 中文按中文学术语序重组，不逐词直译；may/suggest 等对冲在中文中保留为“可能”“提示”，不升级为“表明”“证实”。

## 10. 核查说明（每次都输出）

核查说明是独立的中文文件 `Discussion_核查说明.md`，承担原始提示词所说的“中文说明”。正文不夹带说明文字。按以下顺序写五部分：

登记到 `_process/冲突台账.md` 的新冲突按原表格式追加为表格的新行（紧接上一行，不留空行、不另起小节），编号顺延。

核查说明写给作者看，简洁为先：第 2 部分每条一行，不写工具日志、编码报错、文件哈希、临时文件清单或请求细节；技术问题只在影响核验结论时用一句说明。

1. **需作者裁决或补充的事项**：放在最前。包括材料冲突、`[citation needed]` 缺口、需要 Results 没有的分析才能支撑的论点、需要作者确认的首次性表述或临床意义表述。每条写明问题、正文当前的处理、需要作者给出的决定或材料。没有则写“无”。
2. **合规说明**：逐条对照原始提示词的要求（五部分结构、选准重点、不重复 Results、不超越证据、文献对话、诚实局限、长度、引用、目标期刊策略、输入校验），每条一行，写“已遵循”或“未完全遵循 + 原因”。未指定目标期刊时写明“按通用中高影响力医学期刊规范撰写，未针对具体期刊适配”。
3. **发现—讨论对应表**：每个 Introduction 研究问题和每个 Results 主要发现一行：Results 位置 | 发现（简述，不抄数字）| Discussion 段落 | 处理（展开 / 一句带过 / 未提 + 理由）| 解释的依据（本研究分析或 PMID）| 文献对比的 PMID。表后列出 Discussion 中出现的全部数字及其 Results 出处，逐条标“一致”。

## 11. 修订模式

用户提供已有 Discussion 要求修改时：保留作者已确认的科学主线与引用支持关系，允许同节合并、去重、重排，解决实质叙事问题；前置检查同样适用。附修订摘要并更新核查说明，对保留的问题给出具体证据理由。
