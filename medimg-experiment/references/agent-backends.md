# 自动实验的 CLI 后端

此页仅用于已授权自动模式。科学契约、原始划分、累计预算、正式 seed、审查和冻结测试门对两个后端相同；训练仍由 Python 控制器派发。

## 首次选择

`AdaptiveDelegation@1` 的 `agent_backend` 可为 `codex` 或 `claude`。旧委托省略时按 Codex 解释，不改写历史 JSON 或哈希。首次确认后不自动切换，不因认证、网络、额度或负结果改后端。需要改选时先报告具体范围与影响，不借此重建 study 或重置预算。

| 后端 | 所需字段 | 行为 |
|---|---|---|
| `codex` | `codex.executable` 为核验过的原生程序绝对路径 | 独立 `exec --ephemeral` 只读会话；保留现有接口 |
| `claude` | `claude.executable` 为核验过的原生程序绝对路径，`claude.max_turns` 为 1–100 | 独立 print 会话、每次新 UUID、不持久化/续接、受限只读工具与结构化输出 |

Claude 选择示意（其余科学/预算字段仍按完整模板首次确认）：

```json
{
  "agent_backend": "claude",
  "claude": {"executable": "<已核验原生程序的绝对路径>", "max_turns": 20}
}
```

不把 `.ps1`/`.cmd` 包装脚本拼成 shell 命令。Windows 的 `claude` 可能先找到 npm 包装器，应核对它实际启动的原生程序；保存版本与实际调用记录，不能只凭 `--help` 声称验收。

## 调用权限与证据

两种角色都只返回结构化提案/审查，不能直接执行安装、修改、训练或另启代理。Claude 使用 bare/restricted 模式，只暴露 Read/Glob/Grep 中原生 CLI 实际可用的只读工具及内部结构化输出工具；禁用 MCP、shell、编辑与网络工具。工作目录仅包含受管源码和本次调用材料。权限拒绝须如实记录；受限工具不等于操作系统沙箱，也不能认证人类意图或科学有效性。

调用保留原事件流、结构化结果、实际新会话 ID、后端、实际模型和候选/输入绑定。Claude 必须有匹配的 init 与成功终态、无错误标记及有效结构化输出；缺失/不匹配、超时或达到调用上限均不能登记通过。暂停、截止与失败关闭归属进程树；不能依靠换后端掩盖失败。

Claude 的 `additional_evidence` 只列当前调用的 `adaptive/agents/<invocation-id>/input.json` 或 `invocation.json` 规范相对路径，可为空；不加 study 前缀、括号注释或解释。其他控制元数据已通过 input 提供。实际源码路径放 `artifacts_read`，两者不能混列；结构化接口和本地校验都拒绝不合格式的元数据路径，不通过猜测或裁剪文字获得通过。

故障后的方法分类审查还须核对 input 中的 `method_classification_evidence`：控制器绑定真实旧/新提交、原始提案和批准源码的实际 Git diff，审查者据此独立判断是故障修复还是方法修订。提交不一致、源码不干净、旧提案缺失或差异越界时在调用前阻断；不扩大读取目录或工具权限，也不把提案者自称的“修复”直接当作分类结论。

技术性审查登记协调继续使用 `adaptive-reconcile`；它核验本 study 的实际后端、原生命令、会话事件、输入和候选，不能把 Claude 调用改名为 Codex，也不能解除科学/资源/测试后的人工关口。

## 现有连接配置

后端名称指 CLI 宿主，不保证实际服务模型属于同一厂商。沿用作者本机既有配置，不强制模型、不自动 fallback；调用记录以真实 init 的模型为准。

为避免 bare/restricted 跳过用户配置而继承旧认证，控制器仅在子进程内读取既有 Claude 用户设置中认证与模型连接字段的环境白名单。缺设置时可使用已导出的环境；设置存在但格式无效时停止报告。不会加载用户 hooks/plugins/commands、执行凭据 helper、修改设置或新建凭据仓库。密钥、认证头和环境值不进入 argv、提案或调用回执；不得要求模型读取认证材料。

运行前核验真实调用、允许的源码读取、独立会话与现有服务权限。依赖和服务认证不足时交付准确阻塞原因；协议 fixture/CI 通过不代替真实后端及训练闭环验收。
