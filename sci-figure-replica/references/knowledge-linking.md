# 方法家族与知识关系

## 有边界的联想

联想指方法家族内的推广，例如从来源的 XGBoost＋SHAP，整理到满足条件的机器学习模型＋SHAP。保留来源具体实现，分开写核心目的、成立前提、可推广分支、实现能力、限制和未验证分支。不因散点/箱线画法通用而创建宽泛的新分析方法；共享标签或视觉相似不能证明科学适用。

继续使用 method 页表达家族，不新增家族节点。没有算法的分支先写文字，不自动补算法。家族的适用说明不等于来源代码支持所有分支；代码文件存在也不等于已经运行。

## 每次入库双向检查

新复刻、收录单 panel、拆模板、新增方法或实质修改输入/算法时：

1. 查现有方法、单 panel 图样、可调用模板、接口及反向关系，包括不同来源。
2. 新方法检查能否关联多种图；新图反查能否关联多种方法。核对目的、每行单位、输入输出语义、量纲、配对/重复层级、前提及代码能力。
3. 有依据时在方法页唯一维护 `figure_relations`；图页、反向查询与图谱由同一记录派生。来源/互补方法仍用普通 `[[...]]` 链接，不伪造接口以连通图谱。
4. 正文“知识关联检查”记日期、检查的页面/范围、决定与依据、未知项；未找到关系也说明原因。无须凑数量或保证全网连通。
5. 输入或方法含义改变时复核受影响关系；最后 `save`、`lint`。lint 只检查结构/引用，科学含义仍需 agent 审查。

示例（替换为真实条目与证据，不照抄虚构关系）：

```yaml
figure_relations:
  - figure: templates/example-panel
    compatibility: adaptable
    reason: 本方法输出与图的逐条结果含义一致，表形状需要整理
    prerequisites:
      - 保留同一验证单位与相同量纲
    adaptation: 在课题副本中映射列名并整理长表，不重算统计量
    evidence:
      - 方法输入输出节及图样接口说明的具体位置
    verification:
      state: not_run
      scope: 尚未在课题数据中调用
      evidence: []
```

`figure` 指 `templates/<id>` 或 `layouts/<id>`，可附 `.md`。方法侧维护一次，反向自动显示。

| 关系值 | 显示与含义 |
|---|---|
| direct | 直接可接：可调用模板，语义/粒度/量纲/前提/契约已核对，无需格式适配；不等于真实课题验证 |
| adaptable | 需要适配：有依据的对应关系，说明格式整理或图样待模板化；缺关键科学材料不能伪装成格式问题 |
| candidate | 待核实：有具体依据但仍缺条件，写清未知项，不作为可立即执行方案 |

单 panel 来源图样仅作参考，不可标 direct。页面状态独立于关系；verification 的 `not_run/example/project` 分别是未运行/示例/课题验证，须写 scope 和已有 evidence。不能把一次示例扩大成所有模型已验证。

`/api/relations` 可查全体，`?path=methods/<id>.md` 或图页路径查单条目。摘要/详情同时提供 relations。归档关系保留审计但不进入正式推荐。删除清理同一元数据记录并写审计，不改他页作者备注。

现有 `feeds` 仅表示已声明接口的结构流向，显示为“接口结构匹配”，不自动生成 direct 关系，也不替代科学前提检查。列名相同只是线索；不同名但语义相同的候选应继续查，按 [课题复用流程](project-reuse.md) 在课题副本适配。

## 单 panel、配图与代码

只收录选定的一个逻辑 panel；边缘分布/inset/色标可随主 panel。整图在画廊只读溯源，历史整图来源归档隐藏。图库仅“单 panel 图样”和“可调用模板”。方法配图优先有依据的显式关系，其次有说明的参考图；来源待模板化与代码未验证须写明，无图不放无关图片。

函数中的 n 为实际数据中的任意合法数量，由课题 agent 按既定分组编排，默认保持单 panel 和间距继续增宽/增高；历史模板未适配的如实标明。原生代码与复用代码按 [代码资产](code-assets.md) 保存、查看与复制，不将家族说明当成所有分支已有代码。
