# 自适应实验：首次授权、方法修订与计划回写

仅在医学影像 AI 课题明确要交给 `medimg-experiment` 自主诊断、修订和重训时加载。首版范围为 Windows 本机 2D/3D 分类/分割；普通开题及临床分析沿用原流程。此参考规定科学交接，不承诺 GPU、真实代理调用、无人值守或具体课题可行性已经验证。

## 1. 首次确认与执行授权

保留 G1/G2/G3 真实确认。Codex 提议、作者首次确认具体课题的比较规则、指标阈值和贡献要求，随后用真实授权来源授予执行范围；科学确认不能代替执行授权。授权包含训练、profiling 和允许的自动修订，不能由助手补写“作者已同意”。缺失或模糊的关键项先解决；通用技能不填写统一医学性能阈值。

将以下内容放入当前计划第 0、4、5、9 节及真实 session 来源；实际机器字段按执行技能当次提供的契约/委托模板填写，勿把本清单当作新 schema：

| 交接内容 | 首次必须明确 |
|---|---|
| 固定问题与数据 | 研究目标/任务与输入输出；标签/参考标准；患者或其他独立单位；数据版本/路径与许可；train/val/test 清单、分组审计和冻结身份 |
| 评价定义 | 主指标方向、科学定义/单位/聚合/不确定性、checkpoint 选择和阈值规则、护栏；开发评价实现与科学定义分别登记 |
| 可信比较 | 强基线来源与本机合理水平、公平调参条件、对比/消融、必须支持的贡献目标、效应/区间及反证判定式；文献数字先核对可比性 |
| 分级证据 | 小预算筛选与正式复核的强度、晋级/灰区规则、正式至少 3 seed、患者级输出及统计；3 seed 是最低门槛，不等于统计充分性 |
| 全局上限 | 所有版本累计训练时限、方法修订轮数、故障重试数、单次/步骤超时、绝对截止时间、正式复核预留、最低磁盘余量及估算依据 |
| 可变范围 | 可替换的网络、核心模块、损失、方法假设、训练策略和允许改的代码/配置；不得改变的固定项及接管事件 |
| 环境与资源 | 指定解释器、设备、项目隔离环境、允许的通用依赖及版本、方法源码/权重资源确认清单、许可与来源；不更改全局环境/驱动 |
| 证据与操作 | 初始快照与当前计划、study 路径、通知入口、启动/暂停/恢复/终止、测试暴露状态、可核验的恢复 checkpoint 协议 |

缺 split 时可提初次生成与泄漏审计，作者确认后冻结；不能猜患者分组或因成绩差重新划分。任何训练均需授权，包括计时 profiling；缺估算时先提有明确上限的 profiling 子任务，结果只能在原总上限内自动细化。

训练总账包含基线、比较、消融、多 seed、失败、恢复片段与 profiling；方法修订与故障重试分开计数，同一训练片段不重复扣费。绝对截止时间覆盖实现、审查、网络/人工等待和训练，重启/改版不刷新。探索前检查正式充分训练与比较预留，余量不足即拒绝新探索；任一全局上限到达均有界停止。

## 2. 授权内可变与必须接管

- 网络/模块/损失/方法假设可在已确认可变范围内自动改。每轮记为“依据初始授权的自动修订”，链接原授权、旧新方案、诊断依据、实现/候选与审查；不把新方法写成新的人类确认。原始确认版本和来源不变。
- 固定任务、标签、患者划分、评价科学定义、贡献目标与总预算/截止时间不自动变。想放宽就等待作者裁决，不能重建 study 或改契约重置余额。
- **Q008=B**：整体有优势但模块无贡献，保留该贡献目标，改造或替换实现再验证；不能删除目标、改容易指标或换说法宣布 accepted。预算耗尽报告未达标，保留有效负结果。
- **Q014=B**：公开检索可自主；新增研究源码、模型仓库和权重的具体下载先获作者确认，记录来源/版本/许可。已约定隔离环境内的明确通用依赖可安装并登记影响；`git+pip`、下载带模型代码的包等不能绕过资源确认。
- 开发期可将评价实现恢复到原确认定义，保留错误实现和结果并沿依赖失效；影响 checkpoint/选型时需必要重训。测试分数一旦部分或全部暴露，停止自动方法搜索；明确评价错误也须新的具体作者确认后才能修复/重算测试。
- 用户暂停不自动恢复；权限、登录、额度、数据/磁盘或必须新增下载等障碍进入相应等待/停止。不得自动换账户、扩大额度、上云或上传原始数据。

执行技能负责真实新上下文只读代码审查：改代码后的每个候选训练前重审；代码/命令身份相同、仅换允许 seed 可复用。计划设计审查的 SELF_REVIEW_FALLBACK 不足以代替该训练门。

## 3. 关键事件后真正修订主文

首次受管执行前，把 G3 确认的主文与身份/哈希保存为 study `plans/` 内不可变初始快照。当前计划继续使用 `00_plan/project-plan.md`；原始确认和后续自动修订并列可追溯，不用新版覆盖初始快照。

方法修订、基线核验、筛选/正式复核、失败/评价纠错、复用/失效、恢复、预算停止、冻结和测试后，同一事件更新：

1. **当前技术路线与假设**：修订第 1、3、4 节相应内容。写明旧假设受什么病例/诊断证据挑战，新实现针对什么机制，哪些贡献目标仍未满足。不能只在尾部追加“训练失败”。
2. **下一步与资源**：更新第 9 节任务、依赖、当前预算余额/截止时间与测试暴露状态。最新失败任务和后续诊断任务可见；过时任务不得仍写成下一次将执行。
3. **分开索引三种身份**：最新尝试（可以失败/筛选/失效）、当前有效证据（按条件审查可复用的基线和正式结果）、最终冻结方案（未冻结则明确无）。有效旧基线不因最新候选失败而消失，失效结果不混入当前正式证据。
4. **历史与依赖**：保留全部科学/负结果、失败尝试、评价版本、失效/复用理由和来源 run/提交。依赖条件不变才复用；相关预处理/指标实现/环境改变时检查是否影响选择与结果。

报告要区分科学达标、有效负结果、程序错误造成的失效、预算不足导致的未完成。正式验证的基线/比较/贡献/至少 3 seed 规则全部达标即收敛，预先固定最终模型/seed 清单后统一测试；有余预算也不继续搜索。测试低于预期如实交付，不回到自动换方法。

## 4. 目录、机器登记与实测边界

检测到 `PROJECT.md` 时，计划/记录写入 `00_plan/`，总索引使用 `01_analysis/README.md`；study 默认 `01_analysis/<study-id>/`，保持其受控目录。按 `medpaper-pipeline` 的 study 同步约定：旧的当前计划、review 和索引先唯一归档，PROJECT 仅登记目录说明与变更记录，不新增实验阶段行；受影响下游标 `需返工`，不自动重画/重写。

运行契约、授权与执行命令以 `medimg-experiment` 当前 SKILL/参考为准；不要把本设计字段名当 CLI。只启用已有且经核验的接口；旧 study 不自动迁移。投影写入失败先补完同步，不重复训练。

轻量 Markdown 记录仍是默认。需要完整登记时，沿用 [既有 schema](record-schema.md) 的真实确认与显式 carry-forward；方法/实验/任务登记随当前方案变，原确认来源不改。现有 `validate_plan.py` 只检查登记关系，不执行/审查 runtime 委托、累计预算和冻结门。控制器门或 GPU/无人值守未实测时明确写未验证；合成训练验收不等于真实医学、临床或外部泛化证明。
