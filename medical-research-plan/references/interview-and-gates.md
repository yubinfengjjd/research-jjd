# 访谈、候选与科学确认

## 入口成熟度与第一问

| 入口 | 表现 | 第一问瞄准 | 本阶段产出 |
|---|---|---|---|
| 宽泛方向 | 只有疾病/模态/领域 | 临床问题、使用情景与可得数据 | G1 草案、候选任务族 |
| 有问题无任务 | 有动机，输入输出模糊 | 使用时可得信息与所需输出 | 任务契约草案 |
| 有方法无定位 | 已有模块/模型想法 | 方法要修复的失效及其原因 | 空白与设计原则 |
| 有文献无 idea | 有参考论文，缺贡献 | 共同局限或被忽略条件 | 可辩护空白 |
| 近成熟方案 | 任务、方法、文献俱在 | 最近竞争与反证条件 | 审查计划，可用 synthesize |

混合状态时，除非已有可靠任务契约，先从临床问题与使用时输入问起。已有方案：抽取定义/证据/决定，定位冲突，从最早失效节点接续；不要把有明确材料的用户重新调查一遍。

## 高信息量问题

好问题至少改变以下之一：临床问题、任务、空白、假设、贡献、证据路径、范围边界。优先问会改变多个后续决策的：研究对象、AI 在临床路径中的位置、标签/终点与参考标准、使用时输入、数据可得性与伦理、投稿类型、资源和主要比较。能从授权资料核实的先自行核实；用户决定目标与取舍，不要求用户替 agent 选实现细节。不问“再多说说”式泛问题，要问可区分的选择、例子、失效案例、基线或证据标准。

问题卡格式：

```markdown
**Q{n}** 当前瓶颈：……
问题：……
影响：……
可选：A ……（代价）/ B ……（代价）/ C ……；推荐 X，因为……
```

工具支持单选时不要冒充多选已收齐。只有实际答复更新记录。沉默、预选、“不清楚”和历史助手建议都不是同意；“听你的”只授权当前具体事项代拟。

## 约束盘点

约束分 HARD、PREFERENCE、TARGET/建议默认和 UNKNOWN；写明来源、规则、单位与是否经用户确认。按任务相关性清点：数据类型/访问、伦理审批/豁免与数据协议、标注与读片者资源、参考标准、验证目标、投稿/成果类型、算力/RAM、总时间与截止节点、人力与临床合作者、交付范围和禁止事项。纯临床 CPU 分析不强迫询问 GPU。

投稿类型影响设计权重：方法类（MICCAI/TMI/MedIA 等）重机制新颖性、公平对比与消融；临床类（放射/专科/数字医学期刊）重外部验证、参考标准、读片者对照与临床终点；学位开题或基金按用户模板映射，不改科学逻辑。用户未定时记 UNKNOWN 并说明影响。

启用预设需真实用户选择。当前项目要求覆盖预设并记录旧值；未启用时不要从示例继承眼科、公共数据、外部队列数或 3080 Ti。多个硬条件冲突时回指原声明，提出共同可满足的缩减/替代，由用户裁决关键改变，不能私自牺牲条件。

## 候选比较

G1 后做现状扫描（见证据参考），再提出约 2–3 个机制不同的候选，数量可调整。每个说明临床问题、数据前提、可观察假设、与锚点的差异、强简单比较、决定性证据、资源范围、失败/替代解释和证据状态。先核查硬条件；UNKNOWN 不算通过，失败不能用评分抵消。

可按区分度、因果连贯、可行性、证据可得、可证伪、临床/科学意义 1–5 打分并写出最弱维度；评分只揭示取舍，不自动替用户选赢家。检索后允许重新发散和缩减贡献，保留被拒方向与理由。没有搜索到不等于没人研究，模块组合不自动成为创新。

## 审稿人模拟

接受一项贡献前，让它经受：

1. 最近竞争：同任务、同可得信息、同指标是否已解决？
2. 最简基线：调参、加数据、换预训练/基础模型、预处理能否解释收益？
3. 替代解释：中心/设备/采集差异、标签噪声或捷径特征能否产生同样观察？
4. 负例：方法应在哪里失效或不再有帮助？
5. 反证：什么结果会削弱核心假设，而不只是指标变低？
6. 可行性：数据、伦理、标注、算力、时间是否现实？

回答薄弱时标 PROVISIONAL，并转成必需实验、限制或更窄的主张。

## G1–G3

G1 临床问题与约束：展示临床/科学问题、人群与使用情景、AI 在临床路径中的位置（分诊/替代/辅助/预后/机制理解，如适用）、主要用途、投稿/成果类型、硬条件、偏好和明确排除。宽泛入口此时只确认问题与约束；已有明确任务的用户可同时确认任务草案，但精确任务契约仍在 G2 冻结。

G2 方向、任务与定位：展示选定方向与被拒候选、任务契约（研究对象与单位、使用时输入、输出、标签/终点与参考标准、时间关系、成功标准）、数据来源/版本/访问与伦理证据、独立性前提、锚点论文矩阵与空白类型、核心假设与反证条件。用户选择不能把访问、伦理或标签未知升级为 VERIFIED；证据不足时保持暂定，继续不依赖该事实的工作。

G3 实验与可行性：展示主要比较、实验/分析与敏感性/消融、指标和统计、样本量依据、资源与时间账本、可信性适配及执行边界；确认主要科学取舍。然后才输出完整工程计划和最终主文，之前的段落与任务示意是草案。

确认记录包含节点、对象/版本、用户答复来源和确认内容。科学确认不意味着假设被证明，也不授权实际跑训练或递交伦理。固定科学定义或授权外的重要变化使相关节点 INVALIDATED；边界内细节可修订并说明，不重复整份审批。若首次 G2/G3 已明确可改的方法/假设及不可改的贡献目标，后续依此作方法替换属于授权内自动修订，不因方法变化本身重开 G2/G3；保留原确认，修订记录链接原执行授权，详见 [自适应交接](adaptive-handoff.md)。

synthesize 模式：一次给出 G1–G3 内容，各节点标 UNCONFIRMED，结尾列出需确认的关键决定；用户确认前整体为暂定。

## 状态和退出

阶段 INTAKE → INTERVIEW → POSITIONING → DESIGN → REVIEW → HANDOFF，可按依赖回退。ACTIVE 是正常推进；PAUSED_BY_USER 只来自用户暂停；PROVISIONAL 表示存在待核验/冲突/未确认；READY_FOR_HANDOFF 仅表示设计可交接。

证据 PROVIDED/VERIFIED/INFERRED/PROVISIONAL/UNKNOWN/CONFLICTED，用户确认 UNCONFIRMED/CONFIRMED/INVALIDATED/SUPERSEDED，执行 PLANNED/NOT_STARTED/EXECUTED_UNVERIFIED/EXECUTED_VERIFIED 分开记录，不悄悄升级。

科学关键未知（动摇成立条件）、执行前事项（设计已明确后需完成，如递交伦理、锁定环境）和普通实现选择分别解释影响。不要把前者改名为执行前任务以绕过节点；研究假设尚待实验检验不自动归为前者。

未解决关键缺口时不能出声称条件齐备的最终方案；可交付阶段性材料和明确下一步。开题访谈阶段的搜索/修订最多两轮无进展补查后汇总限制，请用户选择扩大预算/范围或调整方向。已另行授权的自适应实验使用其跨版本修订/故障上限、总训练时限、正式复核预留与整体截止时间；不套用访谈“两轮”出口，也不自动扩大预算或无限自转。
